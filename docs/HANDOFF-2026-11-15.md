## The setup that WORKS (proven this morning)

The hat board, the phone app and the server all go through the **live site**, not the Mac.

1. **iPhone Personal Hotspot:** ON, with **Maximize Compatibility ON**. The board is 2.4 GHz only; with it off, the hotspot ran on 5 GHz and the board couldn't see it.
2. **Hat board** (NULLLAB ESP32-S3 CAM, OV3660, camera attached, pin preset 0): power it from a power bank or USB. It joins the hotspot by itself and POSTs frames to `https://sightline-theta-drab.vercel.app/api/device/frame` (`SERVER_URL` in secrets.h), about every 1.5 s, getting 200s back.
   - Watch the log: `./hardware/flash.sh --monitor` (plugged into the Mac).
   - Reflash: `./hardware/flash.sh`.
   - Live preview: http://172.20.10.3/ (open it from the iPhone).
3. **Phone app (Expo Go):** start Metro on the Mac with `cd ~/sightline/mobile && npm start -- --tunnel --clear`, then scan the QR code.
   - Settings → Server: `https://sightline-theta-drab.vercel.app` (now also the default in `mobile/.env`).
   - Settings → Hat camera: device `hat-01` plus the pair code from `npm run device:code -- hat-01`. Connect.
4. **Test:** hold text 30–50 cm in front of the hat for about 2 s, or press **BOOT** to force a read. The phone speaks the answer.
5. **The Mac is optional** once the app is loaded. The board only needs the power bank plus the iPhone hotspot with signal.

### Why not the Mac server on the hotspot?

The iPhone hotspot isolates its clients: the Mac got `192.0.0.2/32`, and the board can't reach other devices. So the board talks to the live site over the internet instead. Campus Wi-Fi (eduroam/UCSD-Guest) can't take the board at all (enterprise login or a captive portal).

### Known limit on the live site

Auto-reads and the BOOT button work (their state is in Neon). **Spoken commands to the hat** ("read this menu") may fail on Vercel, because the hat's latest frame is held in memory per server instance (lib/frameStore.ts). Use BOOT or auto-read in the demo.
